iDempiere 13 · Spring Boot · Razorpay Payment Links

Send invoices with a payment link, straight from iDempiere

Customers often pay outside the ERP, and someone then matches the payment and keys it in. This project starts to close that loop. Staff run one process in iDempiere to email each customer a secure Razorpay payment link with the invoice PDF. When the customer pays, a Spring Boot service verifies the signed webhook and stores the payment. Posting it against the invoice in iDempiere is the next phase.

How it works

From open invoice to payment

Pick invoices

Run the process in iDempiere with a filter: invoice, date range, partner, document type, organization or due date.

Check eligibility

Paid invoices, credit memos, nothing-open and no-email invoices are skipped and reported.

Create the link

The service creates a Razorpay link for the open amount, or reuses the active one.

Email the customer

The invoice PDF and link go out through iDempiere's standard mail system.

Payment verified

The signed webhook is verified and the paid link is stored. Posting it to the invoice is the next phase.

Features

What you get

Bulk send with safety filters

Filter by invoice, invoice date range, business partner, document type, organization or due date. At least one filter is required, so the process can't email every open invoice by accident.

Smart eligibility

Skips paid invoices, credit memos, invoices with nothing open and invoices with no contact email, and reports sent, skipped and failed counts per invoice.

Link reuse and regeneration

The same invoice and amount reuses the active link. If the open amount changes, the old link is cancelled at the gateway and a new one is issued, so only one live link exists per invoice.

Standard iDempiere email

The invoice PDF is attached and the link is available in mail templates as @PaymentLinkURL@.

Payment history on the invoice

A read-only Payment Links tab shows status, expiry, gateway references and errors, and the current link shows on the invoice header.

Per-organization setup

A configuration window stores the service URL, API key, gateway, bank account, mail template and expiry days. An organization row overrides the client-wide one, with role-based access.

Automatic payment postingNext phase

Paid links become completed iDempiere payments against the invoice, with amount and currency checks. Not released yet.

Engineering

Built to be safe with money

Security

API-key authentication on the service, HMAC-SHA256 webhook signature verification with constant-time comparison, the API key stored encrypted in the ERP, and no secrets in code (environment variables).

Idempotent webhooks

Events are deduplicated atomically with INSERT … ON CONFLICT DO NOTHING inside the same transaction as the state change, so gateway retries are safe and never skipped.

Data integrity

A partial unique index enforces one active link per invoice, stale half-created links are failed automatically, and a payment is flagged as a mismatch when the amount or currency differs.

Gateway-neutral design

Gateway and webhook-adapter interfaces plus a registry. Razorpay is one implementation; a new gateway needs one implementation of each interface plus configuration.

Failure isolation

Each invoice runs in its own transaction, so one failure doesn't affect the rest of the batch. If the mail fails after the link is saved, the link is kept and can be resent.

Native ERP integration

Tables, columns, windows, menu, roles and the process are installed through re-runnable SQL scripts. The plugin is an OSGi bundle with annotation-based process registration and no generated model classes.

FAQ

Common questions

Does it work with iDempiere 13?

Yes. The ERP side is an OSGi plugin for iDempiere 13 on Java 17 and PostgreSQL. A separate Spring Boot service talks to the payment gateway.

Which payment gateway does it use?

Razorpay Payment Links. The service is gateway-neutral, so another provider can be added with one gateway implementation and one webhook adapter, without changing the ERP plugin.

Can it email every open invoice at once?

No, by design. The process needs at least one filter (invoice, date range, business partner, document type, organization or due date), so a bulk send can never go to every open invoice by accident.

What happens if the invoice amount changes after a link was sent?

The old link is cancelled at the gateway and a new one is issued for the new open amount, so only one live link exists per invoice.

Are gateway retries and duplicate webhooks safe?

Yes. Webhook signatures are verified with HMAC-SHA256, and each event is deduplicated atomically in the same transaction as the state change, so retries are never skipped or applied twice.

Does it record the payment in iDempiere automatically?

Payment capture and verification are working. Creating and completing the matching iDempiere payment against the invoice is the next phase and is not released yet.

Has it been used with live payments?

Not yet. It has been developed and tested in Razorpay test mode, including a real payment arriving through a webhook tunnel. Confirm production requirements before going live.
